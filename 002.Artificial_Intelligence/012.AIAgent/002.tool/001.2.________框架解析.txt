就是中间那段【"「把模型说要调什么工具，变成真去执行」"】。

//=============================================== 「框架解析」在干什么？
//=============================================== 「框架解析」在干什么？

模型不会真的 SSH，它只会输出类似：
	新式（function / tool calling）：结构化字段，如 name=query_disk_usage、args={"host_id":"linux-231"}	
		/**
		langchin、spring ai 等框架传工具定义，模型原生支持结构化输出，不单靠提示词。
		所以能输入想要的格式对吧

		格式由工具 schema 约束 — 框架把 name、参数类型、描述传给模型；
		模型在可选工具里选一个，并按 schema 填 args，不是任意自定义格式。

		分两层 — 普通聊天仍走文本；绑定了 tools 时，模型额外返回 tool_calls 结构化块，框架解析后执行，再把结果塞回对话。

		*/
	老式（少数模型）：正文里写 JSON，框架再 正则/JSON 解析 抠出来（你们 demo 里的 fallback）

//=============================================== 框架要做的事：
//=============================================== 框架要做的事：

（1）读 LLM 输出 → 认出「这是工具调用，不是最终答案」
（2）解析 工具名 + 参数
（3）执行 对应 Python/Java 函数（SSH、查库等）
（4）包装 执行结果为 Observation（LangChain 里是 ToolMessage，Spring AI 里类似 tool result）
（5）拼回 对话历史，再调一次 LLM

拼回 对话历史，再调一次 LLM

//=============================================== 循环的关键就在
//=============================================== 循环的关键就在

模型输出 → 框架解析/执行 → 观察结果回灌 → 模型再输出 → …

没有这一步，就只是「聊天」；有了这一步，才是 Agent 的循环（ReAct）。
