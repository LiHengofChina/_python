循环（以及规划怎么用）的 具体跑法
	ReAct、Plan-and-Execute…



//============================== Agent 架构/框架层面的
//============================== Agent 架构/框架层面的

（1）ReAct（推理 + 行动）：虽然其触发方式依赖提示词，
		但它描述的是“推理→行动→观察→再推理”的循环执行架构，
		涉及工具调用和外部环境交互，不仅是提示词技术。


（2）Reflexion（反思）：通过自我评估和记忆反馈来改进后续尝试，
		涉及记忆机制和迭代循环，超出纯提示词层面。


（3）ReWOO 先规划好工具调用，再批量执行，少来回观察


（4）固定工作流 / DAG 步骤图写死或半固定（如 LangGraph 编排），不是自由「想→做→看」


（5）纯 Tool Calling 循环 模型直接出结构化函数调用，框架执行再塞回（思想近 ReAct，形式更工程化）


（6）Plan-and-Execute（规划-执行）：涉及任务分解、分步执行和结果汇总，
		属于Agent 工作流设计，需要额外的执行机制。


（7）Toolformer / 工具学习范式：涉及模型学习何时调用工具以及工具调用的训练/微调，
		属于模型能力训练范畴。


（8）Multi-Agent 协作范式（如 AutoGen、MetaGPT）：涉及多个 Agent 之间的通信、
		角色分工和协作机制，属于多智能体系统架构。


（9）分层/模块化 Agent 架构（如 LangChain Agent、BabyAGI）：
		涉及 Agent 的组件化设计（记忆、规划、工具、执行等模块），属于软件架构设计。



//============================== 属于提示词工程/提示词范式的：
//============================== 属于提示词工程/提示词范式的：

（1）Chain-of-Thought（思维链）：
			通过在提示中引导模型逐步推理，属于典型的提示词技术。

（2）Self-Ask（自问自答）：
			通过提示引导模型先提出问题再回答，属于提示词层面的策略。

（3）Tree-of-Thoughts（思维树）：
			在提示中引导模型探索多条推理路径并评估，可视为提示词技术的扩展。
