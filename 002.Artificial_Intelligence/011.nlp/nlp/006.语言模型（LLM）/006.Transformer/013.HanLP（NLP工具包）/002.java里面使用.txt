//================================================================== HanLP 2.x 与 ERNIE

（1）ERNIE：百度的一类中文预训练语言模型（BERT 系变体），偏「模型本身」。
（2）HanLP 2.x：NLP 工具库，下游任务常用 BERT/ELECTRA/ALBERT 等 Transformer，不一定是 ERNIE。


相同点：都是 Transformer 预训练编码 + 分词/NER 等任务。
不同点：一个是具体模型/生态，一个是可换骨干的框架。
/**

ERNIE：一般用 PaddlePaddle / PaddleNLP，或百度云 API 跑；
		不是必须靠 Ollama（Ollama 主要跑另一类本地 LLM）。

HanLP：可以像库一样直接引入跑。
	   但要注意：常见 Java JAR 多是经典 1.x；
	   2.x 主流是 Python 库，
	   不是「2.x = 随便引个 jar」。

*/

//==================================================================
//==================================================================

2.x 没有「完整本地 Java 库」可直接当模型引擎用。

（1）能当 JAR 本地跑模型的：主要是 HanLP 1.x（com.hankcs:hanlp）。

（1）2.x：本体是 Python；Java 侧官方主要是 hanlp-restful 客户端 JAR，
	 去调 HTTP 服务（官方 API 或自建），不是把 Transformer 模型塞进进程内。

所以：要进程内 JAR → 用 1.x；要 2.x 能力 → Python 本地，或 Java 调 RESTful。

//================================================================== 经典 HanLP（1.x），能协助我后处理姓名
//================================================================== 经典 HanLP（1.x），能协助我后处理姓名

适合做 Java 后处理辅助。

1.x 可进程内 JAR 调用，用人名识别 / 词性 nr 判断「这格像不像人名」，
接到你们现有的行级判断里即可。

注意：
	效果通常弱于 2.x Transformer，少数民族名覆盖一般
	仍建议先剥数字等后缀再喂给它
	地名/状态词（白银、同意）还要靠你们黑名单
结论：做可开关的后处理辅助可行；别指望单靠它换掉整套姓名逻辑。
